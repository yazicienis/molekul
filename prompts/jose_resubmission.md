# MOLEKUL — JOSE Resubmission Plan & Sequenced Prompts

**Context.** The SoftwareX submission (SOFTX-D-26-00486) was rejected: the niche is
already served by PySCF, Psi4NumPy, eChem/VeloxChem, SlowQuant, DQC, pyfock, and
Qiming Sun's "Python for Quantum Chemistry" book. We are **not** resubmitting as a
production code. We reposition MOLEKUL as a transparent, pure-NumPy, single-dependency,
**notebook-based teaching platform** and submit to **JOSE** (Journal of Open Source
Education), whose bar is educational usefulness + documentation + open license + a
clear statement of need, not research novelty.

**Roles.** Claude Code = SUPERVISOR/AUDITOR. Codex = IMPLEMENTER. Codex writes code and

## Load-bearing differentiator (the whole pitch)
Among pure-Python teaching codes, MOLEKUL is differentiated by the *combination*:
1. **NumPy as the sole hard dependency, zero compiled extensions** (SciPy only for
   geometry optimization) — a student can step a debugger from any notebook cell down
   into the Boys function and every integral.
2. **One uniform API across the entire chain**: constants → integrals → SCF → MP2 → CC
   → DFT → excited states → gradients → periodic/phonons.
3. A **14-notebook curriculum** that derives, implements, and PySCF-validates each step.

eChem builds on VeloxChem (compiled), Psi4NumPy on Psi4 (compiled), DQC on PyTorch,
pyfock on Numba. **Every such claim about a competitor must be verified before it is
written** — do not repeat the SoftwareX mistake of mischaracterizing the landscape.

## STANDING RULES (enforce on every step)
1. Never frame breadth as capability ("it even does phonons"). Frame every method as
   **pedagogical coverage**, each backed by a validation number.
2. Freeze scope. Add no methods. Optimize no performance.
3. No half-validated claims. If a method/basis cell fails or is undefined, mark it
   "experimental" in docs or remove it — never claim it.
4. Anchor numbers already verified this session live in `benchmarks/seed_numbers.json`
   (note: PBE is tagged experimental, ~1e-3 Ha grid error; a wrong PySCF reference was
   already found once in NB09 — trust nothing un-re-verified).
